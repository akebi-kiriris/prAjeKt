# Future Backlog

這個目錄專門放「未來可做，但目前先不打進主線 phase」的草稿。

目的有三個：

1. 把臨時想到的改善方向先有地方落地
2. 避免每個想法都直接塞進 `重構計畫.md` 或某個 phase 文件
3. 讓後續要擴充時，可以快速把零散想法收斂成正式規劃

---

## 適合放什麼

1. Agent / prompt / workflow 的下一版想法
2. 某個功能的 backlog 提案
3. 成本、效能、可觀測性、測試策略的後續改進方向
4. 某個頁面或某個 domain 未來可能拆分的設計草稿

---

## 不建議放什麼

1. 已經決定這一階段要做的內容
   - 這類應該進 `docs/phases/`

2. 長期穩定的正式架構說明
   - 這類應該進 `docs/architecture/`

3. 純學習筆記
   - 這類應該進 `docs/learning/`

---

## 命名建議

建議格式：

`Future_<主題>_<日期>.md`

例如：

1. `Future_AgentPrompt分域規劃_2026-06-07.md`
2. `Future_知識庫Agent流程草稿_2026-06-08.md`
3. `Future_任務衝突分析可觀測性_2026-06-09.md`
