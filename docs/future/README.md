# Future 目錄說明

`docs/future/` 用於存放尚未進入主線排程的提案、重構草稿與待驗證方向。這些文件可以有明確主題與技術深度，但尚未作為當前 Phase 的正式執行範圍。

## 內容範圍

本目錄適合存放以下內容：

1. 後續功能或架構的提案文件
2. 尚未排入時程的重構方向
3. 可觀測性、效能、測試策略等後續改善構想
4. 需要先收斂、再決定是否進入主線的設計草稿

## 不建議放入的內容

以下內容原則上不放在本目錄：

1. 已確認納入執行的 Phase 文件
2. 長期穩定且正式採用的架構說明
3. API 契約、錯誤碼或操作手冊
4. 純學習筆記或個人整理

## 相鄰目錄邊界

1. 若文件已進入正式執行階段，應移至 `docs/phases/`
2. 若文件已成為穩定設計基準，應移至 `docs/architecture/`
3. 若文件重點是操作流程，應移至 `docs/runbooks/` 或 `docs/workflows/`
4. 若文件僅作為學習整理，應移至 `docs/learning/`

## 命名原則

建議使用可辨識主題與日期的檔名，例如：

`Future_<主題>_<日期>.md`

## 維護原則

1. 本目錄文件可以保留探索性內容，但主題與適用範圍應寫清楚。
2. 當提案被採納並進入正式規劃後，應移往對應正式目錄。
3. 若內容已失效或被新方案取代，應在文件中標明狀態或整理歸檔。
