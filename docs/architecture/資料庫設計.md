## 使用者系統

### users（使用者帳號）

**用途**: 儲存使用者基本資訊與登入憑證

| 欄位名稱 | 類型 | 說明 | 約束 |
|---------|------|------|------|
| `id` | Integer | 使用者 ID（主鍵） | PRIMARY KEY, AUTO_INCREMENT |
| `name` | String(100) | 使用者姓名 | NOT NULL |
| `username` | String(50) | 唯一用戶名（如 @john_doe） | UNIQUE, NULLABLE |
| `email` | String(120) | 電子郵件 | UNIQUE, NOT NULL |
| `password` | String(256) | 密碼雜湊值 | NOT NULL |
| `phone` | String(20) | 電話號碼 | NULLABLE |
| `avatar` | String(500) | 頭像路徑 | NULLABLE |
| `bio` | Text | 個人簡介 | NULLABLE |
| `is_active` | Boolean | 帳號狀態 | DEFAULT TRUE |
| `last_login_at` | DateTime | 最後登入時間 | NULLABLE |
| `created_at` | DateTime | 建立時間 | DEFAULT CURRENT_TIMESTAMP |
| `updated_at` | DateTime | 更新時間 | DEFAULT CURRENT_TIMESTAMP, ON UPDATE |

**索引**:
- PRIMARY: `id`
- UNIQUE: `email`
- UNIQUE: `username`
- INDEX: `created_at`（用於排序）

**已移除欄位**（課程相關）:
- ~~`student_id`~~ - 學號
- ~~`department`~~ - 科系
- ~~`entry_year`~~ - 入學年份
- ~~`grade`~~ - 年級
- ~~`class_id`~~ - 班級 ID

**對應模型**: `backend/models/user.py` → `User`

**關聯關係**:
- `1:N` → `todos`
- `N:M` → `groups` (through `group_members`)
- `1:N` → `messages`（發送者）

### group_members（群組成員）

**用途**: 多對多關聯表，處理使用者與群組的關係

## 索引策略

### 主要索引
所有主鍵自動建立 PRIMARY KEY 索引。

### 查詢最佳化索引
- **使用者登入查詢**: `users.email` (UNIQUE)
- **群組訊息列表**: `messages (group_id, sent_at)`
- **任務列表**: `tasks (created_by, task_status)`
- **待辦查詢**: `todos (user_id, completed)`
- **已讀狀態**: `message_reads (message_id, user_id)`

### 外鍵索引
所有外鍵欄位都應建立索引以提升 JOIN 效能。

## 資料完整性約束

### 外鍵刪除策略

| 父資料表 | 子資料表 | 刪除策略 |
|---------|---------|---------|
| `users` | `todos` | CASCADE（刪除使用者時一併刪除待辦） |
| `users` | `group_members` | CASCADE（退出所有群組） |
| `groups` | `group_members` | CASCADE（刪除群組時清除成員關係） |
| `groups` | `messages` | CASCADE（刪除群組時刪除訊息） |
| `messages` | `message_reads` | CASCADE（訊息刪除時清除已讀記錄） |
| `tasks` | `task_files` | CASCADE（任務刪除時刪除附件） |
| `tasks` | `task_comments` | CASCADE（任務刪除時刪除留言） |
| `tasks` | `task_users` | CASCADE（任務刪除時清除成員關係） |
| `timelines` | `timeline_users` | CASCADE（時程刪除時清除參與者關係） |
| `users` | `notifications` | CASCADE（使用者刪除時刪除通知） |
| `users` | `activity_logs` | SET NULL（保留日誌但移除使用者關聯） |

### CHECK 約束建議

```sql
-- 使用者狀態檢查
ALTER TABLE users ADD CONSTRAINT check_user_active 
  CHECK (is_active IN (0, 1));

-- 群組類型檢查
ALTER TABLE groups ADD CONSTRAINT check_group_type 
  CHECK (group_type IN ('task', 'class', 'project'));

-- 訊息類型檢查
ALTER TABLE messages ADD CONSTRAINT check_message_type 
  CHECK (message_type IN ('text', 'image', 'file', 'system'));

-- 任務優先級檢查
ALTER TABLE tasks ADD CONSTRAINT check_task_priority 
  CHECK (priority IN (1, 2, 3));

-- 任務狀態檢查
ALTER TABLE tasks ADD CONSTRAINT check_task_status 
  CHECK (status IN ('pending', 'in_progress', 'review', 'completed', 'cancelled'));

-- 待辦優先級檢查
ALTER TABLE todos ADD CONSTRAINT check_todo_priority 
  CHECK (priority IN (1, 2, 3));

-- 時程日期合理性
ALTER TABLE timelines ADD CONSTRAINT check_timeline_dates 
  CHECK (end_date IS NULL OR end_date >= start_date);

-- 檔案大小限制（例如：最大 50MB）
ALTER TABLE task_files ADD CONSTRAINT check_file_size 
  CHECK (file_size IS NULL OR file_size <= 52428800);

-- 通知類型檢查
ALTER TABLE notifications ADD CONSTRAINT check_notification_type 
  CHECK (type IN ('task_assigned', 'message', 'comment', 'deadline', 'mention'));

-- 活動日誌操作類型檢查
ALTER TABLE activity_logs ADD CONSTRAINT check_activity_action 
  CHECK (action IN ('created', 'updated', 'deleted', 'completed'));

-- 活動日誌實體類型檢查
ALTER TABLE activity_logs ADD CONSTRAINT check_activity_entity 
  CHECK (entity_type IN ('task', 'message', 'todo', 'timeline', 'group'));
```

## 重要提醒

### 關於 models/__init__.py 的作用
- **模型註冊**: `__init__.py` 導入所有模型類別，方便其他模組使用
- **Flask-Migrate 偵測**: 必須在 `app.py` 中導入模型，否則 `flask db migrate` 無法偵測到表結構
- **已在 app.py 中加入**: 使用 `with app.app_context()` 導入所有模型，確保 migration 能正確執行

### Migration 前的檢查清單
1. ✅ 所有模型檔案已更新
2. ✅ `models/__init__.py` 已導入所有新模型
3. ✅ `app.py` 已在 app_context 中導入模型
4. 🔲 執行 `flask db migrate` 生成遷移腳本
5. 🔲 檢查生成的遷移腳本是否正確
