## 📝 後端實作

### 新增 `/refresh` Endpoint

**檔案：** `backend/blueprints/auth.py`

**實作內容：**
```python
@auth_bp.route('/refresh', methods=['POST'])
@jwt_required(refresh=True)
def refresh_access_token():
    """使用 refresh token 取得新的 access token"""
    # 從 refresh token 中取得 user_id
    user_id = get_jwt_identity()
    
    # 產生新的 access token
    new_access_token = create_access_token(identity=user_id)
    
    return jsonify({
        'access_token': new_access_token
    }), 200
```

**關鍵點：**
1. **使用 `@jwt_required(refresh=True)`**
   - 不同於一般的 `@jwt_required()`（驗證 access_token）
   - `refresh=True` 參數會驗證 refresh_token
   - 前端需在 Authorization header 放 refresh_token

2. **不從 request body 取 token**
   - Flask-JWT-Extended 會自動從 header 讀取
   - 使用 `get_jwt_identity()` 取得 user_id

3. **只產生新的 access_token**
   - refresh_token 不需要更新（長期有效）
   - 僅返回新的 access_token

#### 2. 實作 Response 攔截器

**完整邏輯：**

```javascript
// Token 刷新相關變數
let isRefreshing = false;  // 是否正在刷新 token
let failedQueue = [];      // 等待刷新完成的請求佇列

// 處理佇列中的請求
const processQueue = (error, token = null) => {
  failedQueue.forEach(prom => {
    if (error) {
      prom.reject(error);
    } else {
      prom.resolve(token);
    }
  });
  failedQueue = [];
};

api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    if (error.response?.status === 401 && !originalRequest._retry) {
      // 1. 防止無限循環
      if (originalRequest.url.includes('/auth/refresh')) {
        localStorage.removeItem('access_token');
        localStorage.removeItem('refresh_token');
        router.push('/login');
        return Promise.reject(error);
      }

      // 2. 防止競態條件（多個請求同時 401）
      if (isRefreshing) {
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject });
        })
          .then(token => {
            originalRequest.headers.Authorization = `Bearer ${token}`;
            return api(originalRequest);
          })
          .catch(err => Promise.reject(err));
      }

      originalRequest._retry = true;
      isRefreshing = true;

      const refreshToken = localStorage.getItem('refresh_token');

      // 3. 沒有 refresh_token，直接跳轉登入
      if (!refreshToken) {
        localStorage.removeItem('access_token');
        router.push('/login');
        return Promise.reject(error);
      }

      try {
        // 4. 呼叫 /refresh 取得新 token
        const response = await axios.post(
          `${BASE_URL}/auth/refresh`,
          {},
          {
            headers: {
              Authorization: `Bearer ${refreshToken}`
            }
          }
        );

        const newAccessToken = response.data.access_token;
        localStorage.setItem('access_token', newAccessToken);

        // 5. 更新原本失敗請求的 header
        originalRequest.headers.Authorization = `Bearer ${newAccessToken}`;

        // 6. 處理佇列中所有等待的請求
        processQueue(null, newAccessToken);

        // 7. 重試原本的請求
        return api(originalRequest);
      } catch (refreshError) {
        // 8. refresh_token 也過期，跳轉登入
        processQueue(refreshError, null);
        localStorage.removeItem('access_token');
        localStorage.removeItem('refresh_token');
        router.push('/login');
        return Promise.reject(refreshError);
      } finally {
        isRefreshing = false;
      }
    }

    return Promise.reject(error);
  }
);
```

## 🔑 關鍵技術說明

### 1. 為什麼用 `axios.post()` 而不是 `api.post()`？

| 方式 | 說明 | 問題 |
|------|------|------|
| `api.post()` | 會經過攔截器 | Request 攔截器會加 access_token（我們要用 refresh_token）<br>Response 攔截器收到 401 可能無限循環 |
| `axios.post()` | 直接呼叫，繞過攔截器 | ✅ 避免循環，可自訂 header |

### 2. 防止競態條件（Queue 機制）

**問題情境：**
```
用戶同時發送 3 個 API 請求
↓
3 個請求同時收到 401
↓
如果沒有 queue，會同時呼叫 3 次 /refresh ❌
```

**解決方案：**
```javascript
let isRefreshing = false;     // 刷新鎖
let failedQueue = [];         // 等待佇列

// 第一個 401 請求
if (!isRefreshing) {
  isRefreshing = true;        // 上鎖
  // 執行刷新邏輯
  processQueue(null, newToken);  // 處理佇列
  isRefreshing = false;       // 解鎖
}

// 後續的 401 請求
if (isRefreshing) {
  failedQueue.push({ resolve, reject });  // 加入等待佇列
}
```

**運作流程：**
```
請求 A → 401 → 開始刷新（isRefreshing = true）
請求 B → 401 → 加入佇列等待
請求 C → 401 → 加入佇列等待
    ↓
刷新完成（取得新 token）
    ↓
processQueue() 讓 B、C 都用新 token 重試 ✓
```

### 3. 防止無限循環

```javascript
// 檢查是否為 refresh endpoint 本身失敗
if (originalRequest.url.includes('/auth/refresh')) {
  // 不要再次嘗試刷新，直接跳轉登入
  router.push('/login');
  return Promise.reject(error);
}
```

### 4. 防止重複重試

```javascript
if (error.response?.status === 401 && !originalRequest._retry) {
  originalRequest._retry = true;  // 標記已重試
  // 執行刷新和重試邏輯
}
```

## 💡 學習筆記

### `@jwt_required()` vs `@jwt_required(refresh=True)`

| 裝飾器 | 驗證的 Token | 用於 | Header 需放置 |
|--------|-------------|------|--------------|
| `@jwt_required()` | access_token | 一般 API 端點 | `Bearer <access_token>` |
| `@jwt_required(refresh=True)` | refresh_token | `/refresh` 端點 | `Bearer <refresh_token>` |

### Queue（佇列）機制簡單理解

**Queue 就像排隊：**
- 第一個人（請求）去辦事（刷新 token）
- 後面的人（請求）排隊等待
- 辦完事後，大家一起用結果（新 token）繼續

**在程式中：**
```javascript
let failedQueue = [];  // 排隊的人

// 有人來排隊
failedQueue.push({ resolve, reject });

// 辦完事，通知所有排隊的人
failedQueue.forEach(prom => {
  prom.resolve(newToken);  // 給你新 token，可以繼續了
});
```
