## 4. frontend consumer 第一輪對齊

這一輪另外補了幾個已被 OpenAPI 與 backend response contract 點出來的前端漂移點：

1. `auth`
   - 補上 `AuthLoginResponse`、`CurrentUserResponse` 前端型別
   - `auth store` 不再靠未定義 shape 硬吃 `/auth/login`、`/auth/me`
2. `upcoming`
   - `taskService.upcoming()` 改為 `UpcomingTaskRaw[]`
   - `timelineService.upcoming()` 改為 `UpcomingItem[]`
   - `HomeView.vue` 移除原本的 `as unknown as ...` response cast
3. `groups snapshot`
   - 補上 `GroupSnapshotGenerationResponse`
   - `GroupsView.vue` 改用 union + type guard 處理同步快照 / 背景 job 回應
4. `profile stats`
   - `profile store` 移除不必要的 `Task[]` / `Timeline[]` response cast

這一批的目標不是大改前端架構，而是先把幾個還明顯綁著舊 response 假設的 consumer 收回到目前 backend contract / OpenAPI 可證明的 shape。

另外又補了一輪尾端收斂：

1. `copilot / agent`
   - 補上前端 `CopilotAgentToolsResponse`、tool descriptor、tool payload map、step input/output 外層型別
   - `copilotService.ts` 不再把 `/copilot/agent/tools` 寫成匿名 `Record<string, unknown>[]`
   - 保留真正動態的 `result` / tool-specific data 為彈性欄位，不假裝已完全定版
2. `cast cleanup`
   - `GroupsView.vue` 移除 `storeToRefs(...) as unknown as Ref<...>` 類型強轉
   - `ProfileView.vue` 移除 `chartStats` 與 `ownedTimelines[0]` 的多餘 cast
   - `auth store` 的 `/auth/me` 回應改成顯式 mapping，不再用 `as User` 硬轉

這一批比較像 10.3 的尾端清理：不是新增新 contract，而是把前端還殘留的「我自己假設它就是這個型別」慢慢退掉。

再下一輪又補了幾個「shape 判讀型」收尾：

1. `timelineDetailUtils.normalizeGeneratedTasks`
   - 不再把 payload 先硬轉成 `Record<string, unknown>` 再取 `.tasks`
   - 改為先檢查 `tasks in payload` 再處理
2. `ProfileView.vue`
   - `status_distribution` 轉 pie data 時，改用 `isStatusKey(...)` 做型別收斂
   - 不再直接 `k as StatusKey`
3. `TimelineViewModes.vue`
   - FullCalendar `extendedProps.timeline` 改成先檢查是不是 `Timeline`
   - frappe-gantt popup 的 task 讀取改成先檢查是不是 `FrappeTask`

這一輪的目的，是把「本來只是為了拿到欄位而硬 cast」的地方，改成先確認 shape，再往下用。這樣比較符合 10.3 想建立的契約思路。

最後又補了一輪共用型別收束：

1. `common.ts`
   - 抽出遞迴 `JsonValue` / `JsonObject`
2. `copilot.ts`
   - `CopilotMcpExecuteResponse.result` 從 `unknown` 收斂成可描述但保留彈性的 `JsonValue`
   - `trace.metadata`、step data、tool payload map 全部改接共用 JSON 型別
3. `group.ts` / `timeline.ts`
   - `metadata`、`event_payload` 改接共用 JSON 型別
4. `services/api.ts`
   - refresh / retry 攔截器改用 `AxiosError<JwtErrorPayload>` 與較明確的 request header 型別處理
5. `auth store`
   - `register(...)` 不再吃 `Record<string, unknown>`，改用明確表單型別

這一輪算是把 10.3 從「模組契約收斂」一路收到了「前端共用型別語意一致」。

## 5. 本輪刻意不改的地方

1. 不把所有 list endpoint 改成 `{ data: [...] }`
2. 不把 service 已穩定輸出的大型 analysis / AI payload 硬拆成單一通用 envelope
3. 不把 download / preview blob response 放進 JSON contract
4. 不改 frontend 已依賴的 key，例如 `task_id`、`group_id`、`invite_code`、`message_id`

這些保留不是漏做，而是為了避免 10.3 變成破壞式 API 改版。
