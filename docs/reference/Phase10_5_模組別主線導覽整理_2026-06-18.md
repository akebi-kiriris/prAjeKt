# Phase 10.5 模組別主線導覽整理

> 日期：2026-06-18  
> 範圍：`tasks`、`timelines`、`knowledge`、`groups / messages / notifications`、`copilot / agent` 的閱讀路線與入口整理。  
> 定位：本文件是「怎麼讀這個專案」的導覽，不是新的 API 規格書，也不取代 Phase 10.4 的契約狀態矩陣。

---

## 1. 使用方式

這份文件的用途很單純：當我想回頭理解某個模組時，不用從整個 repo 亂翻，而是照一條固定路線走。

建議讀法：

1. 先看該模組的「這條主線在做什麼」
2. 再照「建議閱讀順序」打開檔案
3. 先理解資料如何從 UI 進 service，再看 backend route / service / contract
4. 最後才看 tests
5. 如果看到「不必現在深挖」，就先不要鑽進去
6. 如果看到「可能留給 10.6」，代表那是後續差異清理或鬆動點檢查，不是 10.5 要修

10.5 的重點是建立心智地圖，不是把每條路都走到最底。

---

## 2. 共用閱讀規則

大部分模組可以用同一種順序讀：

1. `frontend/src/views/` 或 `frontend/src/components/`
   - 看使用者從哪裡操作
2. `frontend/src/stores/`
   - 看頁面狀態和 action 怎麼包
3. `frontend/src/services/`
   - 看實際 API wrapper 與 path
4. `frontend/src/types/`
   - 看 frontend 對 request / response 的理解
5. `backend/blueprints/`
   - 看 HTTP route、payload 進入點、錯誤映射
6. `backend/contracts/`
   - 看 request / response shape
7. `backend/services/`
   - 看真正業務流程
8. `backend/tests/` / `frontend/src/**/__tests__/`
   - 看行為與 contract 是否被守住

如果只是想重新抓方向，先看到第 4 步通常就夠了；要修問題時才往 backend service 和 tests 深挖。
