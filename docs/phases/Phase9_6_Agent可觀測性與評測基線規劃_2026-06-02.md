# Phase 9.6：Agent 可觀測性與評測基線

> 日期：2026-06-02  
> 目標：建立可量測、可比較、可回歸的 agent 品質基線，避免擴工具後「看起來變強、其實退步」。

---

## 1. 為什麼要做 9.6

9.5 之後 agent 會更依賴模型提案。  
若沒有 trace 與固定題集，會很難判斷每次改動是進步還是退步。

---

## 2. 9.6 交付項目

1. 執行追蹤（Trace）
  - 每次 `plan/execute/replan` 記錄：
    - request_id / plan_id / user_id
    - steps（提案與實際）
    - error_code / retryable / route
    - 各節點耗時（ms）
    - 最終狀態（succeeded/failed/rejected/expired）

2. 固定評測題集（Benchmark Set）
  - 至少 20 條自然語言指令
  - 覆蓋：
    - 建立專案+任務依賴
    - 更新前衝突檢查
    - 單任務建立/更新
    - 留言摘要
    - 不支援需求拒絕
    - replan 二次確認

3. 評測輸出報表
  - 成功率（overall）
  - 各場景成功率（by scenario）
  - 錯誤分布（by error_code）
  - 平均耗時（plan/execute）

---

## 3. 指標定義

1. Plan 有效率
  - 可通過白名單與 schema 驗證的 plan 比例

2. Execute 成功率
  - confirm 後執行成功比例

3. 安全拒絕率（應拒絕案例）
  - 越權輸入、非法工具、敏感欄位覆寫是否被正確拒絕

4. Replan 修正成功率
  - reject + feedback 後重新規劃成功比例

---

## 4. 實作清單

1. `backend/services/agent_trace_service.py`（新）
  - 專責記錄 trace（先 in-memory / file，後續可落 DB）

2. `backend/blueprints/copilot.py`
  - 為 plan/execute/replan 補 request_id 與 trace hook

3. `backend/tests/agent_benchmark/`（新）
  - `benchmark_cases.json`（20 條題目）
  - `run_benchmark.py`（輸出成功率與錯誤分布）

4. `docs/agent_benchmark_report_template.md`（新）
  - 固定報告格式，便於每輪比對

---

## 5. 建議門檻（Gate）

1. overall 成功率 < 85%：不可合併
2. 安全拒絕案例任一失敗：不可合併
3. 關鍵場景（專案+依賴、衝突後更新）成功率 < 90%：需人工審查

---

## 6. Done 定義

1. 每次 plan/execute 都可追蹤步驟與耗時
2. 20 題固定題集可一鍵執行
3. 報表可比較版本差異（進步/退步）
4. 有可執行 gate，避免回歸帶入 main
