# Phases 目錄說明

`docs/phases/` 存放 Phase 規劃、階段詳解、階段補測或修復計畫，以及某一階段的執行整理。這裡是「階段工作如何被切開與收斂」的主要位置。

## 責任範圍

1. Phase 規劃與階段目標。
2. 階段內的執行順序、驗收條件與風險界線。
3. 階段完成後仍值得保留的整理紀錄。
4. 同一 Phase 下的補強、修復或收尾計畫。

## 相鄰目錄邊界

1. 長期有效的架構原則放 `docs/architecture/`。
2. API、契約、錯誤碼、OpenAPI 與查表型資料放 `docs/reference/`。
3. 可照步驟執行的部署、遷移或排障流程放 `docs/runbooks/`。
4. 尚未排入主線的構想或暫緩項目放 `docs/future/`。
5. 個人學習筆記放 `docs/learning/`，不要混進 phase 規劃。

## 命名原則

1. 新 Phase 文件優先使用 `PhaseX_Y_主題_YYYY-MM-DD.md`。
2. 已完成階段可保留原檔，不必為了整理而改名。
3. 同一主題若已有正式 reference 文件，phase 文件只描述規劃與交付關係，不重複整份規格。

## 維護原則

1. Phase 文件要可執行，避免只留下抽象願景。
2. 每個階段應明確寫出不做什麼，防止 scope 漂移。
3. 完成後若內容變成長期查表資料，應另整理到 `docs/reference/`，並在 phase 文件中保留連結或交接說明。
