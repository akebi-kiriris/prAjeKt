## 2. 優先修正項目

### P0：Agent 執行例外後不可永久卡在 `executing`

相關位置：

- `backend/services/copilot_service.py`
  - `execute_copilot_agent_plan()`
- `backend/services/agent_plan_service.py`
  - `AgentPlanStore.mark_executing()`
  - `AgentPlanStore.mark_executed()`
  - `AgentPlanStore._expire_unsafe()`

目前流程會先將 plan 標記為 `executing`，再呼叫 `execute_copilot_agent_request()`。若 agent 執行過程直接拋出例外，後續 `mark_executed(..., succeeded=False)` 不會執行。

此外，`_expire_unsafe()` 目前只處理 `planned` 狀態，因此失敗 plan 可能永久停留在 `executing`。

建議先新增測試暴露問題，再修改實作：

```text
test_execute_plan_marks_failed_when_agent_execution_raises
```

驗證重點：

- mock `execute_copilot_agent_request()` 拋出例外。
- 呼叫 `execute_copilot_agent_plan()` 後應回傳或拋出明確錯誤。
- plan 最終狀態應為 `failed`，不可停留在 `executing`。
- 再次執行同一 plan 時，應回傳可理解的 `409 CONFLICT`。

### P0：補齊 Copilot Agent Blueprint HTTP 邊界測試

相關位置：

- `backend/blueprints/copilot.py`
- `backend/tests/blueprints/conftest.py`
- 建議新增：`backend/tests/blueprints/test_copilot.py`

目前 production app 已註冊：

```text
/api/copilot
```

但 Blueprint 測試 fixture 尚未註冊 `copilot_bp`，因此以下新增 API 沒有 HTTP 層測試：

- `GET /api/copilot/agent/tools`
- `POST /api/copilot/agent/plan`
- `POST /api/copilot/agent/execute`
- `POST /api/copilot/agent/reject`
- `POST /api/copilot/agent/replan`

建議案例：

| API | 測試案例 |
| --- | --- |
| `/agent/tools` | 未登入回 `401`；登入後回傳 registry 清單 |
| `/agent/plan` | body 非 JSON object；缺少或空白 `message`；正常建立 plan |
| `/agent/execute` | 缺 `plan_id`；`confirm` 非 bool；`max_loops` 非整數；`max_loops <= 0` |
| `/agent/execute` | 找不到 plan；跨使用者 plan；執行完成後重複送出 |
| `/agent/reject` | 缺 `plan_id`；找不到 plan；正常拒絕 |
| `/agent/replan` | 缺 `message`；舊 plan 拒絕失敗時仍可依規格處理；模型重規劃失敗 |

### P1：補齊 Tool Handler Adapter 測試

相關位置：

- `backend/services/tools/handlers.py`
- 建議新增：`backend/tests/services/test_tool_handlers.py`

目前 graph 測試會 mock `execute_registered_tool()`，registry 測試也只驗證 fake handler delegation，因此還沒有充分確認 concrete handler 是否正確：

- 驗證 Pydantic input。
- 呼叫對應 service。
- 將 domain error 映射成統一 error envelope。
- 將 service output 包成統一 success envelope。

第一輪不必為 11 個 handler 各寫大量案例，可先挑代表類型：

| 類型 | 建議 handler | 驗證重點 |
| --- | --- | --- |
| 寫入 | `handle_create_task_for_user()` | 參數傳遞、成功 envelope |
| 權限 | `handle_update_task_for_member()` | service 回 `403` 時映射正確 |
| 查詢 | `handle_list_tasks_for_user()` | 回傳清單 envelope |
| 外部服務 | `handle_generate_timeline_tasks_with_ai()` | `503` 是否可重試 |
| 輸入驗證 | `handle_upload_and_index_knowledge_document()` | 空白 filename/content 回 `VALIDATION_ERROR` |

每個代表 handler 至少補：

- 正常 payload。
- 缺少必要欄位。
- service 拋 domain error。

### P1：補齊 Tool Error Mapper 與 Agent Retry 路由

相關位置：

- `backend/services/tools/error_mapper.py`
- `backend/chains/agent_nodes.py`
- 建議新增：`backend/tests/services/test_tool_error_mapper.py`
- 補充：`backend/tests/chains/test_agent_graph.py`

目前已有 `VALIDATION_ERROR -> ask_user` 測試，但其餘錯誤語意尚未完整驗證。

建議案例：

| 輸入 | 預期 |
| --- | --- |
| Pydantic `ValidationError` | `VALIDATION_ERROR`、不可重試 |
| domain error `403` | `PERMISSION_DENIED`、立即 `stop` |
| domain error `404` | `NOT_FOUND`、進入 `ask_user` |
| domain error `409` | `CONFLICT`、進入 `ask_user` |
| domain error `503` | `UPSTREAM_UNAVAILABLE`、可重試 |
| domain error `504` | `UPSTREAM_TIMEOUT`、可重試 |
| 非整數 `status_code` | 降級為 `INTERNAL_ERROR` |
| 已達 retry limit | 停止重試並進入 `stop` |

Agent graph 補測時，應確認重試次數不會無限增加，且停止後的 `final_answer` 可讓前端理解失敗原因。

### P2：補 transaction unexpected exception 分支

相關位置：

- `backend/services/transactions.py`
- 建議新增：`backend/tests/services/test_transactions.py`

目前既有測試會間接走過 transaction helper，但 unexpected exception fallback 分支仍未命中。

建議案例：

```text
test_transaction_rolls_back_and_wraps_unexpected_exception
test_transaction_rolls_back_and_reraises_domain_error
test_transaction_commits_when_block_succeeds
```

驗證重點：

- 成功時呼叫 `commit()`。
- domain error 原樣拋出，但仍呼叫 `rollback()`。
- 未預期例外轉成指定 domain error，保留 fallback message 與 status code。

---

### P2：整理測試 teardown 的 SQLite connection warning

Coverage 模式下可看到多筆：

```text
ResourceWarning: unclosed database in <sqlite3.Connection ...>
```

建議確認：

- `backend/tests/conftest.py` teardown 是否需要補 `db.session.close()`。
- 是否有背景 executor、AI async job 或額外 app context 在測試結束後仍持有連線。
- 是否只在 coverage / GC 時機下出現，或一般 pytest 也能穩定重現。

此項目前不阻塞功能，但應避免未來 CI 把 warning 升級為 error 後才處理。
